## 3. 🔴 VPS-M21 — La section sécurité devient aveugle un jour sur sept, du côté rassurant

C'est le constat le plus important du passage, et il porte sur **l'audit lui-même**.

Voici ce que la collecte a affiché ce matin à 02 h 22 :

```
── Tentatives d'intrusion ──
  fenetre du journal : 2026-08-09T00:05 → 2026-08-09T02:22
  echecs dans /var/log/auth.log : 0
  dont sur le compte root : 0
  top IP en ECHEC :
  comptes vises :
  dernier echec : aucun dans la fenetre
```

Trois listes vides et deux zéros. Lu vite — et un rapport quotidien se lit vite — cela dit
« personne n'attaque cette machine ».

**La cause est mécanique.** La section ne lisait que `/var/log/auth.log`, le fichier *courant*.
`logrotate` tourne chaque samedi à minuit ; à 02 h 22 un dimanche, ce fichier contient **2 h 17**
d'histoire. Le reste était dans `auth.log.1`, que rien n'ouvrait :

```
/var/log/auth.log     0 echecs   fenetre 2026-08-09T00:05 -> 2026-08-09T02:25
/var/log/auth.log.1 188 echecs   fenetre 2026-08-02T00:01 -> 2026-08-08T23:59
```

**Ce que la fenêtre tronquée cachait**, une fois le correctif appliqué et relancé :

```
  fenetre analysee : 2026-08-02T02:31 → 2026-08-09T02:31  (7 jours glissants)
  echecs sur 7 jours : 184  (soit ~26/jour)
  dont sur le compte root : 28
  top IP en ECHEC :   24 27.79.0.171 | 18 27.79.44.3 | 18 162.243.102.104
  comptes vises :     16 foodsqan | 16 admin | 4 test | 4 centos | 3 rebecca
  dernier echec : 2026-08-08T05:50:15
  ── repartition par jour ──
    73 2026-08-02 | 1 2026-08-03 | 98 2026-08-04 | 9 2026-08-05 | 3 2026-08-08
```

**Pourquoi c'était invisible.** Le collecteur **affichait honnêtement sa fenêtre** depuis le
premier jour — la ligne `fenetre du journal` est là. Mais elle est passée inaperçue cinq
passages durant parce que la fenêtre faisait alors 3 à 6 jours : elle *ressemblait* à une
mesure hebdomadaire. Ce n'est qu'au jour de la rotation qu'elle s'effondre à 2 h — et ce
jour-là, le chiffre qu'elle produit est **rassurant**, donc personne ne le remet en cause. Un
défaut qui alarme à tort se corrige en une journée ; un défaut qui rassure à tort survit.

C'est **VPS-M11 et VPS-M20 pour la troisième fois**, sur un troisième objet : *une mesure
dérivée d'une source qui tourne doit porter la durée de sa fenêtre, et cette fenêtre doit être
la même à chaque passage.* Sinon on ne compare pas des attaques, on compare des rotations.

**Le correctif est appliqué** (§8.a) : lecture de `auth.log` + `auth.log.1`, bornée à **7 jours
glissants**, avec le taux par jour et la répartition quotidienne. Coût mesuré : **0,05 s**.

Le correctif est inchangé depuis quatre rapports. Effet : rend exécutable le script de

```bash
chmod +x /opt/vizyo-verify/deploy/vps/backup.sh
```


```bash
sed -i 's|^ExecStart=/opt/vizyo-verify|ExecStart=/bin/bash /opt/vizyo-verify|' /etc/systemd/system/vizyo-verify-backup.service && systemctl daemon-reload
```

**L'ordre compte** : lancer le service avant le `chmod` échoue en `203/EXEC` et brouille la
