## 3. 🆕 Le repère de repli désigne la bonne image sous un nom faux — VPS-051

**VPS-051 · 🆕 VPS-M129 · gravité 3 · 🆕 V43**

### Ce que la collecte a dit (et qui était faux)

```
tracky-api  🔴 le repli MENT : tracky-api:avant-20260928-1909-ee134038 = 72f95e127711, mais le conteneur tournait sur 11ad5120fb74 le 2026-09-28
tracky-web  🔴 le repli MENT : tracky-web:avant-20260928-1909-ee134038 = aa9c56a1f2c3, mais le conteneur tournait sur 208474b25fd1 le 2026-09-28
```

Le bloc comparait le repère à l'image du passage d'hier (02 h 30), avec **six déploiements** entre les deux. Et sa vérification de
secours (VPS-M116), la « chaîne », a échoué pour deux raisons, qu'aucun des deux défauts n'annonçait.

### Ce que la marge a établi (lecture seule : `docker images`, `docker inspect` sous `timeout 20`, journal T33, `git log`)

| Repère | Image | Née | Le déploiement de son nom | L'image réellement en service avant ce déploiement |
|---|---|---|---|---|
| `avant-20260928-1909-ee134038` | `72f95e127711` | 12:51:14 | `ee134038`, fin 19:14:24 | ✅ elle-même : mise en service à 15:42 par `436d9ffe` |
| `avant-20260928-1537-436d9ffe` | `baecee3f24b7` | 09:56:30 | `436d9ffe`, fin 15:42:42 | ✅ celle de `d09aa605` (11:41) |
| `avant-20260928-1338-00606db4` | `baecee3f24b7` | 09:56:30 | `00606db4` : **aucune ligne T33** | le même : un passage de 13 h 38 a posé ses repères puis n'a rien recréé (*« trois heures de guichet fermé »*, `9a3bbfbb`) |

**L'image est la bonne, c'est le nom qui ment.** `etiqueter_repli` lit `git rev-parse --short HEAD` **avant** son propre `git pull`
(`deploy.sh` l. 695-699). Cela suffisait tant que personne ne tirait avant lui. Depuis le 27/09, la préversion sur la démo fait `git pull`
et `compose build` sur le VPS **avant** `deploy.sh` : quand le repère reçoit son nom, `HEAD` est déjà le code entrant. Le 27/09 encore, le
nom portait le code sortant (`avant-20260927-1810-908d20a0` pour `a3a8be21`).

**Pourquoi c'est un constat.** En incident, on choisit un repli **par son nom**. `deploy.sh --repli avant-20260928-1909-ee134038` rend
`436d9ffe`, pas `ee134038`. Le repère le plus récent reste juste, puisque c'est « le précédent ». Mais tout choix fondé sur le sha tombe un
cran trop loin. S'y ajoute le passage refusé de 13 h 38 : ses repères occupent une des trois places de `REPLIS_A_GARDER` sans ajouter
aucune profondeur de repli.

**Pourquoi la chaîne de M116 échouait aussi.** Elle exige que l'image du repère soit **née pendant** son déploiement. Or `436d9ffe` ne
touchait que le web. L'API déployée à 15 h 42 est donc sortie du **cache**, et elle date de 12 h 51. Un build n'est pas une naissance.

### Le geste (V43) : dans `deploy.sh`, hors de l'audit

Nommer le repère d'après le **dernier sha du journal T33** (`tail -1`, champ `sha`), qui est par construction le code en service, et ne
revenir à `HEAD` que si le journal est vide. En complément, poser les repères **après** `garde recreation`, ou les retirer quand la garde
refuse. Et, pour que la preuve devienne possible, **journaliser l'`ImageId`** à côté des `containerId`.
**Gain** : un nom de repli qui dit la vérité. **Risque** : faible (harnais `deploy.test.sh`, 170 contrôles). **Contrepartie** : une lecture de
fichier de plus. ❌ Ne pas renommer les repères existants à la main : les trois prochains déploiements les élagueront.

### Le correctif du collecteur (VPS-M129)

Quand la chaîne ne se prouve pas, le bloc teste une **plausibilité** avant de crier. Le repère doit pointer une image présente,
**différente** de celle en service, et **née avant la fin de l'avant-dernier déploiement journalisé**. Il écrit alors qu'il s'agit d'une
plausibilité, pas d'une preuve. **Banc** (VPS, 1,2 s) :

```
tracky-api  ✅ repli PLAUSIBLE : tracky-api:avant-20260928-1909-ee134038 = 72f95e127711 — image nee 12:51:14 UTC, AVANT la fin du deploiement precedent (436d9ffe, 2026-09-28T15:42:42Z) et differente de l image en service
            ⚠️ PAS une preuve d identite : le journal T33 ne porte pas l image de chaque deploiement.
               Et le NOM du repere peut porter le sha ENTRANT (preversion tiree avant deploy.sh) — VPS-M129.
tracky-web  ✅ repli PLAUSIBLE : tracky-web:avant-20260928-1909-ee134038 = aa9c56a1f2c3 — image nee 15:40:12 UTC, AVANT la fin du deploiement precedent (436d9ffe, 2026-09-28T15:42:42Z) et differente de l image en service
```

### ⚠️ La leçon de ce passage

**Une vérification écrite un jour donné encode les habitudes de ce jour-là.** M116 avait été écrit le 24/09, un jour où chaque déploiement
reconstruisait l'API et où personne ne tirait le code avant `deploy.sh`. Quatre jours plus tard, deux habitudes ont changé : les builds
passent par le cache et la préversion tire le code. La règle est devenue fausse sans que le code bouge. Le remède n'est pas une heuristique
de plus : c'est une **donnée** qui manque au journal, l'`ImageId`.

### b. Angles morts restants

1. **Le journal T33 ne porte pas l'image de chaque déploiement.** Sans elle, la vérification du repli reste une plausibilité. *Piste* : V43
   (côté `deploy.sh`), puis la chaîne se prouve par égalité. **1ᵉʳ report.**
2. **Rien ne surveille le CPU servi ni les forks de `sshd` entre deux passages.** **45ᵉ report.**
3. **Les cadences de healthcheck (78 / min) ne sont pas ventilées par conteneur.** **10ᵉ report.**
4. **Le collecteur ne dit pas si une tâche du poste l'a refusée** (réveil `missed=1`, 3ᵉ matin). *Piste* : la tâche d'audit écrit
   `NumberOfMissedRuns` et `BatteryStatus` dans un fichier que le rapport lit. **3ᵉ report.**
5. **Un déploiement forcé dans la fenêtre du matin n'est pas signalé comme tel.** Le bloc T33 imprime `force=true` sans croiser l'heure
   avec la garde. *Piste à coût nul* : 🟠 si `force=true` et l'heure de Paris est entre 05:30 et 09:00. **1ᵉʳ report.**
6. **Un objet NEUF n'est plus suivi dès le lendemain** (VPS-048 J+6). **7ᵉ report.**
7. **Les heures UTC d'`ordonnancement` glisseront le 25/10.** **6ᵉ report, échéance le 25/10.**
8. **Les fiches `APPLIQUE` ne sont re-mesurées par rien.** **22ᵉ report.**
9. Code de sortie des `guest-exec` (8ᵉ) ; certificats : 2 domaines sur 29 (19ᵉ) ; séries non alignées sur l'heure (VPS-M103, 11ᵉ). *L'ancien
   n° 5 (« latest ≠ production » ne reconnaît pas une préversion) est sans objet ce matin, la préversion étant retombée ; il reviendra à la
   prochaine.*
